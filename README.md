# DSA Pattern Explorer

A staged path through data structures and algorithms, from first principles to
competitive. 6 stages, 19 categories, 57 topics, 830 practice problems, with
implementations in Python, C++ and TypeScript.

Next.js (App Router) + React 19, statically exported. No database, no API, no
server — every page is prerendered HTML.

## Running it

Requires **Node 22** (pinned in `.nvmrc` and `netlify.toml`).

```bash
npm install
npm run dev      # http://localhost:3000
npm run check    # validate content (runs automatically before build)
npm run build    # static site in out/
npm start        # serve the built output locally
```

### `npm run check`

Runs before every build via `prebuild`, so a content mistake fails locally
rather than on Netlify. It checks:

1. **Each data file parses on its own.** A stray `` `identifier` `` inside a
   template literal closes the string early; the bundler's error then points
   at a line nowhere near the cause. This names the file.
2. **Topic ids are unique** — routes are keyed by id, so a duplicate silently
   shadows a page.
3. **Required fields are present** — a missing title breaks routing, a missing
   summary leaves an empty roadmap card.
4. **Every topic is on the roadmap exactly once** — an unplaced topic still
   gets a page, but nothing links to it.
5. **No duplicate problems** within a difficulty bucket.
6. **Complexity strings parse** onto the ruler scale, so no topic renders a
   ruler with no marker.
7. **SVG diagrams have a `viewBox` and an `aria-label`.**

## Deploying to Netlify

`netlify.toml` is already configured — connect the repo and it works with no
dashboard settings:

```toml
[build]
  command = "npm run build"
  publish = "out"

[build.environment]
  NODE_VERSION = "22"
```

`next.config.mjs` sets `output: 'export'`, so `next build` writes a plain
static site to `out/`. Netlify serves it straight from the CDN with no
serverless functions and no `@netlify/plugin-nextjs` involved.

`trailingSlash: true` emits `/topic/two-pointers/index.html` rather than
`.../two-pointers.html`, which is what Netlify's static server expects for
clean URLs.

**If you later add server-side rendering, API routes, or ISR:** remove
`output: 'export'`, drop `publish` to `.next`, and install
`@netlify/plugin-nextjs`. Nothing here needs it today.

## Routes

| Route | What it is |
| --- | --- |
| `/` | The roadmap — six stages, every topic in learning order |
| `/topic/[id]/` | One prerendered page per topic (57 of them) |

Topic pages are generated by `generateStaticParams`, each with its own
`<title>` and description.

**`params` is a Promise.** From Next 15, the `params` argument to a page and
to `generateMetadata` must be awaited — reading `params.id` directly still
works in 15.x but logs a deprecation warning on every render, and is removed
in Next 16. Both are `async` and destructure `const { id } = await params`.
`generateStaticParams` is unaffected and still returns a plain array. Where two topics share a title — "Traversal" belongs
to both Linked Lists and Trees — the page title is qualified with the category
so a shared link is unambiguous.

## Structure

```
src/
  app/
    layout.jsx              fonts, global CSS, providers, shell
    page.jsx                the roadmap
    topic/[id]/page.jsx     generateStaticParams + metadata per topic
    not-found.jsx
  components/
    Providers.jsx           progress + language, shared across routes
    Shell.jsx               two-column frame; the rail persists on navigation
    Sidebar.jsx             two-level navigator, filter, progress
    Roadmap.jsx             staged learning path
    TopicView.jsx           the topic page layout
    Walkthrough.jsx         long-form explanation sections
    ComplexityRuler.jsx     places time complexity on a growth scale
    CodeBlock.jsx           Python / C++ / TypeScript tabs, copy button
    ProblemList.jsx         three difficulty columns with checkboxes
    Illustration.jsx        renders a topic's diagram markup
  data/
    index.js                assembles categories, applies enrichment
    roadmap.js              the 6 stages and their topic ordering
    topics/*.js             one module per category — core content
    enrichment/*.js         walkthroughs + C++, merged in by topic id
  lib/complexity.js         parses "O(n log n)" into a ruler position
  styles/                   tokens, layout, illustration classes, code theme
```

### State across routes

With one page per topic, component state resets on navigation, so solved
problems and the selected code language live in a context provider in
`layout.jsx`. Both are read from `localStorage` **in an effect, not during
render** — the pages are prerendered as static HTML, and touching
`localStorage` while rendering would produce markup that disagrees with the
build output and trip React's hydration check.

Progress is keyed by problem URL, so a problem listed under two topics is a
single checkbox.

### Fonts

Loaded with a stylesheet `<link>` rather than `next/font`, deliberately.
`next/font` downloads faces during `next build`, which makes every deploy
depend on Google Fonts being reachable from the build machine — a network blip
there fails the whole build. A link tag degrades to the fallback stack instead.
To self-host, put `.woff2` files in `public/fonts` and switch to
`next/font/local`.

## Adding a topic

Append to the `topics` array in the relevant `src/data/topics/*.js`:

```js
{
  id: "arrays-my-pattern",        // unique across the whole library
  title: "My Pattern",
  subtitle: "Arrays",
  summary: "One line for the sidebar and roadmap cards.",
  complexity: {
    time: "O(n log n)",           // one clean expression — the ruler parses this
    space: "O(n)",
    note: "Caveats go here, not in `time`.",
  },
  walkthrough: [
    {
      heading: "What it actually does",
      body: ["Paragraph one.", "Paragraph two."],
      trace: `worked example, monospace, alignment preserved`,
      aside: "The thing everyone gets wrong here.",
    },
  ],
  useCases: ["When to reach for it"],
  pitfalls: ["Common mistakes"],
  code: { python: `...`, cpp: `...`, typescript: `...` },
  problems: {
    easy: [{ name: "Two Sum", url: "https://leetcode.com/problems/two-sum/" }],
    medium: [], hard: [],
  },
}
```

Then add its id to a stage in `src/data/roadmap.js`. Every topic must appear on
the path exactly once — `generateStaticParams` builds a page for each, and an
unplaced topic is unreachable from the roadmap.

**Watch for nested backticks.** Code and trace fields are template literals, so
a stray `` `identifier` `` inside one ends the string and breaks the build.

## Deep walkthroughs

Topics carry a `walkthrough`: titled sections with prose, optional monospace
`trace` blocks for worked examples, and an optional `aside` callout.

Older topics get theirs from `src/data/enrichment/`, keyed by topic id and
merged over the topic in `data/index.js`. That layer exists to retrofit content
written before the walkthrough schema — **new topics should carry everything
inline** in their category file, as the Hash Tables topics do.

**All 57 topics are written up.** Every stage is complete:

| Stage | | Topics |
| --- | --- | --- |
| 1 | Foundations | 9 / 9 |
| 2 | Core Patterns | 9 / 9 |
| 3 | Trees, Heaps & Graphs | 11 / 11 |
| 4 | Algorithm Design | 13 / 13 |
| 5 | Weighted Graphs & Maths | 8 / 8 |
| 6 | Advanced | 7 / 7 |

implementations for all 57.

## Illustrations

Older topics use HTML built from the utility classes in
`styles/illustration.css`. Newer ones use inline SVG, which can show state
progressing through an algorithm rather than restating it in a box. SVG
diagrams use the `dg-*` class vocabulary at the bottom of that stylesheet, so
colours come from the palette rather than hard-coded fills:

| class | use |
| --- | --- |
| `dg-cell`, `dg-cell-idle` | a slot; idle means out of play |
| `dg-cell-live`, `dg-cell-hit`, `dg-cell-out` | active / matched / rejected |
| `dg-cell-mark` | pointer target |
| `dg-link`, `dg-link-hi`, `dg-link-cut` | pointers between nodes |
| `dg-ptr`, `dg-ptr2` | pointer labels |
| `dg-label`, `dg-index`, `dg-note`, `dg-title` | text roles |
| `dg-good`, `dg-bad` | outcome annotations |

Give every diagram a `viewBox` so it scales, plus `role="img"` and an
`aria-label`.

## Possible additions

The roadmap is complete. Topics that would extend it rather than fill it in:

- **Strings** — Manacher's, suffix arrays, Aho-Corasick
- **Sorting** — counting/radix/bucket sort as topics in their own right
- **Arrays** — cyclic sort, matrix traversal (spiral, rotate in place)
- **Trees** — serialize/deserialize, Morris traversal, balanced BST internals
- **Graphs** — strongly connected components, bipartite checking, max flow,
  bridges and articulation points
- **Range Queries** — sparse table, persistent segment trees
- **Advanced** — sqrt decomposition, Mo's algorithm, game theory,
  computational geometry, digit DP
